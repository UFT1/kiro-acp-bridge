BEFORE YOU CONNECT

Company account? Get your sponsor’s approval.

Obtain written approval from your project/account sponsor and Kiro administrator before company-managed use. Kiro/AWS permission for this provider-style ACP flow is unresolved; sponsor approval does not override vendor terms. Personal users must also confirm permission.

THE HANDOFF, NOT THE TAKEOVER

One clear boundary.
You stay in control.

Kiro supplies the next response or tool request. OpenCode decides what happens on your machine.

01 / CONNECT
⌁

Use the official interface.

The adapter starts your installed Kiro CLI through ACP. No extracted Kiro credentials or private inference endpoints.

02 / HAND OFF
⇄

Keep execution in OpenCode.

Tool schemas become MCP handoff tools. The first tool request returns to OpenCode; the inner Kiro turn is cancelled.

03 / CONTINUE
↵

Follow your permission flow.

OpenCode executes or denies the request, then sends the result in the next inference step. No second set of tool approvals.

Full setup documentation ↗
01

Clone & test offline

No Kiro login, inference, or credits needed for these tests.

git clone https://github.com/UFT1/kiro-acp-bridge.git
cd kiro-acp-bridge
npm test
02

After approval, connect your CLI

Use your own login. Choose an exact model ID available to your account; never paste a subscription credential into the bridge.

kiro-cli chat --list-models --format json
03

Start locally. Configure OpenCode.

Replace the example model ID. Keep this terminal running.

export KIRO_ACP_MODELS="YOUR_EXACT_MODEL_ID"
npm start

In a second terminal, from the clone, set the same model ID (and any custom port/key settings). Generate your configuration:

export KIRO_ACP_MODELS="YOUR_EXACT_MODEL_ID"
node configure.mjs

Merge the printed provider entry into your existing OpenCode config, then select kiro-acp/<your-model-id> in /models. Do not replace unrelated settings.

HONESTLY EXPERIMENTAL

Know what’s on
the other side.

A working prototype, not a production gateway or a faithful raw-model API.

CONTEXT

A fresh session per step.

The full transcript is reconstructed for each request. Long sessions, caching, and exact history fidelity need further validation.

VISIBILITY

Unknown is not free.

Token usage, credit cost, and reasoning statistics are not reported. A zero in OpenCode does not mean zero Kiro usage.

CAPABILITIES

Text. Tools. One at a time.

No images or structured output. One tool handoff per request. Sampling and reasoning-effort controls are not forwarded.

SECURITY

Local, not a sandbox.

The endpoint is loopback-only and key-protected. Kiro still runs as your user, receives your context, and may retain sessions.

Live-tested during development: Kiro CLI 2.31.0 · explicit v2 ACP engine · OpenCode 2.0.25. Other versions and accounts need their own validation.
